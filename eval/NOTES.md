# 评测集的已知问题（人工复核时必读）

这份评测集由 AI 分身收集、我人工过了一遍。**样本本身的 ground truth 不是完美的**，
所以看准确率时必须连带看这份说明，否则会误读数字。

---

## 🔬 Tavily 参数实测（2026-10-08，v11 之前）

动手前把每个候选参数**实测了一遍**，结果推翻了两个我原本的判断。

### `include_domains`：是**硬过滤**，不是加权

查询「低钠盐是送命盐 辟谣 真相」：

| | 返回 | 其中来自辟谣平台的 |
|---|---|---|
| 不限定 | 6 条 | 1 条（其余：新浪、知乎、某医院、某校、`py.fjsen.com`） |
| `include_domains=[piyao.org.cn, kepuchina.cn, fact.qq.com]` | 3 条 | **3 条（全部）** |

而且限定结果里那条 `piyao.kepuchina.cn` 的 **score 与不限定完全一致**（0.81524754）
→ 它是在**同一批候选里过滤**，不是重新排序。

**边界（这才是风险所在）**：

- `include_domains=["this-domain-does-not-exist-xyz123.com"]` → **0 条**
- `include_domains=["gov.cn"]` 配同一条辟谣查询 → **0 条**

`gov.cn` 是真实且规模极大的域名，配辟谣查询居然也是 0 条 —— 说明候选池里只要
没有该域名的结果，就空手而归，**不会自动放宽**。

**据此定的设计**：只给「辟谣路」做定向。它本来就只想要辟谣平台的结果，
而且它空了还有中文/英文/新闻三路兜底。
**对中文/英文路做定向是拿召回换精准，不做。**
（上线后实测确认：6 路检索里有 1 路辟谣返回了 0 条，其余三路照常把结论撑起来。）

### `exclude_domains`：有效，机制是**腾出结果位**

`max_results` 是固定的 4~5 个位子，垃圾占一个就少一个权威来源。

| 查询 | 基线 A/B 级 | 排除内容农场后 |
|---|---|---|
| 低钠盐是送命盐 | 1/5 | **2/5**（挤进 `piyao.org.cn` A + 人民网 B） |
| 隔夜水 致癌 亚硝酸盐 | 2/5（含一个 YouTube D） | 2/5（换成 `piyao.org.cn` A + 新华网 B） |

注意：`sources.py` **本来就压住了 D 级**（模型不许拿 D 级下结论）。
所以这里省的是 token 和干扰，**不是"防模型用错来源"**。

### `country`：**实测变差**，推翻了"顺手白捡"的假设

查询「个人养老金制度 全国 实施」：

| | 结果 |
|---|---|
| 基线 | 5 个中国政府站，**全是 A 级**（`rst.ln.gov.cn`、`chinatax.gov.cn`、`csrc.gov.cn`…） |
| `country="china"` | 混进 `baike.baidu.com`（D 级）、`metlife.com.cn`（当事方）、`12371.cn` —— **明显更差** |

而且 `country="cn"` → **HTTP 400 Bad Request**，**整个请求直接失败**。

**结论：不做。** 值写错会把检索全废掉，而正确取值的效果是负的。

### 刻意不做清单

| 参数 | 理由 |
|---|---|
| `country` | 见上（实测变差 + 非法值 400） |
| `auto_parameters` | 会让 Tavily 替我们改 `search_depth` 等参数，破坏"知道自己发了什么请求"这个前提 |
| `/research` | 自主多轮研究并**直接给结论**，与本项目"只信一手来源、自己分级"的哲学正面冲突；4~250 credit/次 |
| `search_depth=advanced` | 我们已经自己抓正文，它的"内容更长"价值已被覆盖，价格却翻倍 |
| `time_range` / `start_date` / `end_date` | 与现有的 `topic=news + days` 用途重叠，不另加旋钮 |

### 🐞 顺路发现的两个 tier 表问题（**未修，需要单独验证**）

1. **`.edu.cn` 被判成 A 级「官方一手」，但提示词说"高校 = C 级「专业机构」"。**
   实测：`btch.edu.cn`（某校医院科普页）在一条辟谣查询里被判 A 级。
   这与提示词里 `C 专业机构：科普机构、医院、高校、学术数据库` 的定义**直接矛盾**。
   改动它会影响"哪些来源够格支撑判定"，属于行为变更，**必须单独跑评测验证再动**。
2. **`news.sina.cn` 漏判成"未分级"** —— `D_DOMAINS` 里只有 `sina.com.cn`，
   而 `sina.cn` 是两个不同后缀。（这条已在 v0.8.0 修掉；`edu.cn` 那条还留着。）

## 🧪 全文抓取 A/B 实验（2026-10-08，v10）

**改了什么**：以前判定只看搜索返回的摘要片段；现在对够格下结论的来源（默认 A/B 级）
再抓一次网页正文（`fetch.py`），每条断言最多 3 页、每页 3000 字，
并在提示词里标明每条证据是「全文」还是「仅摘要」。

### 结果：16/19 (84.2%) vs 14/19 (73.7%)，**+2 条**

| | 全文开 | 全文关 |
|---|---|---|
| 准确率 | **16/19 = 84.2%** | 14/19 = 73.7% |
| token | 343,380 | 285,224（+20%） |
| 抓到的正文 | 约 96 页 / 81 万字 | 0 |

### 设计：这是**配对**对照，不是比两个总分

断言（`cache_claims`）、检索结果（`cache_search`）两臂**全部走缓存、完全一致**，
唯一变量就是 `check.py` 里有没有调 `fetch.enrich()`。所以任何逐条差异都只能
来自证据正文，而不是"这次搜到的网页不一样"。

### 逐条归因（关键：把翻转拆开看动机）

| 样本 | 关 | 开 | 归因 |
|---|---|---|---|
| **t05** | 不符 ❌ | **混合 ✅** | **干净战果**。开的理由明确写了"苏州文件明示机关事业单位女职工及男职工护理假津贴仍拨付单位，措辞绝对而存成文例外" —— 这正是摘要里没有、正文里才有的**成文例外**，就是设计这个功能时假设的机制。 |
| **t01** | 混合 ❌ | **可信 ✅** | 归因成立，但**方向和我预想的相反**：不是"看到例外所以更谨慎"，而是**更多正文让它更敢下结论**（它看到"覆盖一孩二孩三孩"，就认为"每个孩子"不算被绝对化）。这次恰好撞对了 ground truth。 |
| **u01** | 混合 ❌ | 可信 ❌ | **反方向**。两臂都错（期望"不足"），但开的那一臂从"混合"走到了"可信" —— 沿**过度自信**方向离正确答案更远。理由同样是"更多正文让它更敢下结论"。 |
| r04 | 不符 ✅ | 不符 ✅ | **与全文无关**。开的那一臂原本在这里报 `JSONDecodeError` 崩掉；修掉拆断言缺 JSON 兜底的 bug 后才判对。这 +1 是健壮性修复，**不许算进全文抓取的功劳**。 |

### ⚠️ 这次实验最有价值的发现：同一个机制在两个方向上起作用

"给模型更多正文"**不是单向变好**。两个方向的例子都出现了：

1. **看到摘要漏掉的成文例外 → 收敛成 `mixed`**（t05，对）
2. **看到支持性原文 → 丢掉 `mixed` 的谨慎、变得更确定**（t01 撞对、u01 撞错）

第 2 条是危险的：对一个事实核查工具来说，**过度自信比过度谨慎坏得多**。
u01 就是活样本 —— 它本来就答错了，全文抓取把它推向了更错的答案。

**所以下一步该动的不是检索，是提示词**：要明确告诉模型
"证据更长 ≠ 可以下更强结论；正文里看到支持性表述，不构成放宽 `mixed` 门槛的理由"。

### 噪声警告：+2 恰好在门槛上

`NOTES` 前面记过噪声下限 **±1 条**。Δ=+2 只比门槛高一条，
**不能宣称"统计显著"**。之所以还敢用这个结论，是因为：

- 3 条翻转**每一条都能归因到一个具体机制**（见上表），没有一条说不清；
- **r01~r10（10 条谣言）两臂都是 10/10**，全文抓取没有在核心用例上造成回归；
- 两臂的断言和证据完全相同，"证据不同"这个最大的噪声源被消掉了。

**但判定这一步本身仍不确定**（见下文"根因"一节）。要更硬的结论，
需要两臂各跑 3 票（`JUDGE_VOTES=3`，成本 ×3）。

### 这次实验暴露并修掉的两个真 bug

1. **拆断言没有 JSON 兜底**：三级兜底只写在「判定」那一步，拆断言直接
   `llm.parse_json(raw)`。r04 就死在这里 —— 模型第一条断言吐了被截断的 JSON，
   整条样本报错、白花掉前面所有的钱。现在两步共用 `_chat_json`，
   失败降级成"无法判定"而不是崩溃。
   > 顺带修正：`NOTES` 早先把 r02 的 `JSONDecodeError` 归到判定那一步，
   > **归错了**，实际是拆断言这一步。判定那步本来就有兜底。
2. **拆断言缓存被下游改写污染**：`gather_evidence` 就地往 claim 上挂 evidence，
   而 `extract_claims` 把**同一个对象**存进缓存 → 下一次任意样本触发落盘时，
   整份缓存连证据一起写进磁盘。实测 19 条跑完，
   `cache_claims.json` 从 281 字节涨到 **496KB**，里面塞满整页网页正文。
   现在存取都走副本。
   > **判定结果不受影响**：`gather_evidence` 里 `c["evidence"] = _pick(pool, cap)`
   > 是无条件覆盖，陈旧证据一定被丢弃。坏的是缓存卫生和磁盘占用。
3. **`run_eval.py` 的 `--resume` 会删数据**：复用分支 `continue` 跳过了
   `dump_partial`，于是 `--resume --redo <id>` 把 `.partial.json` 覆盖成
   "只跑到被重跑那条为止"的前几行。**实测踩过：两臂各 19 条的完整结果被截成 4 条。**
   已修。

### 计量工具本身也出过错（记下来当教训）

第一版的"治疗剂量"埋点，是在跑完一条之后**再调一次** `extract_claims` 去数证据 ——
读到的是缓存副本，会被同进程里已改写过的对象干扰。结果**"关全文"的那一臂也显示
"全文 6/12 条"**，数字完全是假的。

**计量工具出错比没有计量更危险**：它会让你得出一个自信的错误结论。
现在剂量直接从 `run_one` 手上的 claims 里数。

## ⛔ 最重要的结论：**现在的评测分辨不出 1 条样本的差别**（2026-10-04）

这一条比下面所有实验都重要，**做任何"提高正确率"的改动之前先读它**。

### 证据

v8 跑到 v9 之间，我**没有做任何针对 t04 的改动**，但 t04 自己从「判成不符（错）」
变成了「判成混合（对）」。

**这就是噪声下限：至少 ±1 条。**

而 v9 相对 v8 的总变化，正好就是 1 条（15/19 → 14/19）。

### 这意味着什么

**任何"只改 1 条样本"的结论都不可信** —— 包括我上面那些实验里"改进了""退步了"的说法。
19 条样本 + 单次运行，分辨率不够。

### 根因：**不在拆断言，在「判定」这一步**（2026-10-04 实测修正）

之前的判断是"拆断言的措辞每次略不同 → 关键词变 → 缓存未命中 → 证据变 → 结论翻转"。
**这个链条是真的，但它不是全部 —— 我把它证伪了一半。**

**实测过程**：
1. 实现了「拆断言缓存」（按文本固定拆分结果，见 `check.py` 的 `SPLIT_VERSION`）；
2. 用 `--limit 5` 连跑两次同一个 5 条子集；
3. 核对缓存：**拆断言缓存 5 条全命中、检索缓存 241 条** —— 也就是说，
   两次运行的**断言、关键词、检索结果完全相同**；
4. **r05 还是翻了**：第一次判成「不足」（错），第二次判成「不符」（对）。

**结论：判定这一步本身就不确定。`temperature=0` 不等于确定性输出。**

（旧 NOTES 里那句"把证据固定住、只反复调判定 3 次 → 3/3 完全一致"，
是在**1 个样本 × 3 次**上得到的 —— 样本量太小，当时就写明了"不能当成普遍保证"。
今天这个反例正好印证了那句免责。）

### 所以现在该怎么办

固定拆断言（`SPLIT_VERSION` 缓存）依然**该留着** —— 它消掉了一个真实噪声源、
让判定拿到的输入是确定的、还省了重复的拆分调用。**但它不足以让评测可复现。**

真正能压住判定噪声的只有两条：

1. **多次取多数**：`.env` 里 `JUDGE_VOTES=3`（**功能早就实现了，默认关闭**）。
   代价是判定成本 ×3。
2. **多轮取平均**：同一份代码跑 3 遍完整评测，看多数结果。

**在做了其中一条之前，不要再靠"跑一次评测看分数"来做判断。**
19 条样本 + 单次运行，分辨率不够；而噪声的下限至少 ±1 条（约 5%）。

## 🧪 v9 实验：「权威冲突必须判 insufficient」硬规则（2026-10-04）

**改了什么**：判定提示词加第 11 条 ——
*A/B 级来源之间明确冲突、且无更高层级来源裁决时，必须判 `insufficient`*，
并加了反向约束防止它退化成"万能挡箭牌"。

### 结果：**未获统计显著验证**（准确率 15/19 → 14/19，但这个差在噪声内）

| 样本 | 变化 | 能不能归因到新规则 |
|---|---|---|
| u03（NMN） | 不符 → **不足** ✅ | **能**。这正是规则针对的情形，是它唯一的干净战果 |
| t04 | 不符 → 混合 ✅ | **不能**。没有任何针对 t04 的改动，纯粹是噪声（见上文） |
| t01 | 可信 → 混合 ❌ | **不能**。它给的理由谈的是 mixed 的门槛，不是新规则 |
| t05 | 混合 → 可信 ❌ | **不能**。理由谈的是 A 级来源支持，不是新规则 |
| r02 | JSON 解析出错 ❌ | **不能**。模型吐了坏 JSON，与判定规则无关 |
| u01 / u04 | 仍未修好 | 规则没有触发 |

**归因分析**：三条退步的理由里**都没有出现新规则的机制**。
**所以没有证据表明是规则害的，也没有证据表明它整体有效。**

### 保留这条规则的理由（诚实版）

1. 它修好了唯一一个干净的样例（u03），方向正确；
2. 没有证据表明它有系统性危害；
3. 它理论站得住：权威之间没定论时给确定答案是这类工具最危险的错误模式。

**但它未经统计显著验证。** 以后有人说"v9 加了条规则提升了准确率" —— 那是错的。

### 同时暴露的两个独立问题

- **r02 报 `JSONDecodeError`**：`_judge_once` 设计了一次重试，这次两条都没成。
  这是独立的健壮性 bug，与判定规则无关，**尚未修复**。
- u01（阿斯巴甜）**规则没触发**：模型认为 IARC 与 JECFA 的说法不冲突，
  而是"各自成立"。这条规则想覆盖的情形，比预想的更难被模型识别。

## 🧪 v8 实验：并行检索 + 辟谣检索（2026-10-04）

**改了什么**：① 检索从串行改成并发（限并发 4）；② 每条断言多搜一路「辟谣 / fact check」。

**结果：准确率一模一样。**

| 指标 | v7（改前） | v8（改后） |
|---|---|---|
| 准确率 | 15/19 = 78.9% | 15/19 = **78.9%** |
| 失败样本 | t04 / u01 / u03 / u04 | **t04 / u01 / u03 / u04（完全一致）** |
| 总耗时 | 545s | **373s（-31%）** |
| 总 token | 243,640 | **224,320（-8%）** |

**辟谣检索确实起作用了**（查 `cache_search.json` 里这一路搜回的域名）：

| 辟谣路 | 次数 | 对照：中文/英文路 | 次数 |
|---|---|---|---|
| `piyao.kepuchina.cn`（科普中国辟谣） | 18 | facebook.com | 9 |
| `news.cn`（新华社） | 15 | youtube.com | 9 |
| `xinhuanet.com` | 8 | pmc.ncbi.nlm.nih.gov | 9 |
| `piyao.org.cn`（中国互联网联合辟谣平台） | 5 | baike.baidu.com | 8 |

它精准勾到了辟谣平台，而对照组只勾到 ×5。**但它没有改变任何一条判定** ——
提供的是佐证，不是新结论。

### 🔍 这次实验最有价值的产出：定位到了真正的瓶颈

剩下 4 条失败里，**3 条（u01/u03/u04）都是「尚无定论」类**。

**结论：这不是检索问题，是判定规则问题。**
工具在这些话题上已经搜到了 A/B 级权威来源，再多喂权威来源也改不了结论 ——
它缺的不是证据，是一条「**当 A/B 级来源之间明确冲突、且没有更高一级来源裁决时，
必须判 `insufficient`**」的硬规则。

**所以下一步该动提示词，不该再动检索。** 别再往检索上加东西了。

### ⚠️ 同时修掉的一个隐形漏洞

`run_eval.py` 原来走 `check.run()` 的默认 `use_cache=True`。
**19 条样本跑过一次后全进了结果缓存，之后不管你改什么代码，第二次评测都会
原样返回旧结论。** 也就是说：这个工作流跑第二轮之后，测的就不是当前代码了。

已改成 `check.run(cfg, case["text"], use_cache=False)`。
同时把 `PROMPT_VERSION` 7→8（检索策略也算「流程」，改了必须让缓存失效）。

> 如果你在别处复现评测，**记得确认没有命中结果缓存** —— 否则会得出
> "改动没效果"的错误结论，而且极难察觉（数字稳定得可疑就是信号）。

## ⚠️ 最新发现：波动全部来自「尚无定论」这一类（2026-10-03）

工具迭代了 4 个版本，每一版都跑了全量评测。**把结果按类别拆开看**：

| 版本 | 假消息（10条） | 真消息（5条） | 尚无定论（4条） | 总分 |
|---|---|---|---|---|
| v5（收紧 mixed） | **10/10** | 4/5 | 1/4 | 15/19 |
| v6（双语检索+未分级修复） | **10/10** | 4/5 | 2/4 | 16/19 |
| v7（当事方官网+国际来源） | **10/10** | 4/5 | 1/4 | 15/19 |

**看出规律了吗：「明确为假」这一类四个版本全是满分，一次没掉过。**
78.9% ~ 84.2% 之间的全部波动，都发生在「尚无定论」那 4 条上。

**更要紧的是**：逐条看 u01/u03/u04 的判定理由，工具给出的结论**都有 A/B 级来源支撑**，
而且往往比我标的 ground truth 更细：

- **u03（NMN）**：工具把「NMN 是返老还童神药」判为不符（21经济网：只有小鼠实验+市场炒作），
  把「好多明星都在吃」判为可信（澎湃、界面新闻确有报道）。**两条都对**，但我标的是"证据不足"。
- **u04（染发剂）**：工具用 A×4 来源（福建药监局、NCI、FDA、PMC）分别判定
  「会致癌」不符、「等于慢性自杀」不符、「合格的没事」部分属实。**看起来很合理**。

**所以结论是**：这不像是"工具过度自信"，更像是**我给这 4 条标的「证据不足」本身就有问题**——
我把"话题有争议"当成了"无法判定"，但工具实际上能找到足够权威的来源去判。

**下一步该做的**：不急着改标签（那会显得像为了让分数好看而改答案），
而是**重新设计"尚无定论"类的样本**——真正找那种"连 A 级来源都互相矛盾、谁也没有定论"的例子。
现在的这 4 条达不到这个标准。

## 📉 一次回归事故的完整记录（2026-10-03，值得一读）

为了让"主属实、末句说过头"的消息不被误判成假话，我给工具加了第 4 档判定 `mixed`（部分属实）。
**结果准确率从 89.5% 掉到 73.7%。**

原因是模型把 `mixed` 当成了"拿不准时的折中档"，大批本该判 🔴 的谣言被改判成 🟠：

| 样本 | 原文 | 误判理由 |
|---|---|---|
| r02 | 紫菜是黑塑料袋做的 | "紫菜泡水撕不烂"这句确实是事实 → 部分属实 ❌ |
| r07 | 低钠盐是送命盐 | "吃了会得高钾血症"对**肾病患者**成立 → 部分属实 ❌ |
| r10 | 鸡蛋过敏不能打流感疫苗 | 部分说明书确实列了禁忌 → 部分属实 ❌ |

**修法两处**：

1. **收紧 `mixed` 门槛**：必须同时满足"核心主张被 A/B 级来源正面支持"+"同一来源指出成文例外"+
   "原话措辞绝对"三条；并明确禁止两种情况——核心主张已被否证（判 refuted）、
   例外面向另一类特定人群（如肾病患者）而原话是对一般人的断言（判 refuted）。
   还写了一句：**mixed 不是折中档，不许当保险选项用。**
2. **总判定里 `refuted` 优先于 `mixed`**：只要有一条断言被明确否证，整条消息就不该被当可信。
   （"紫菜撕不烂"是真，"所以是塑料袋做的"是假 —— 这条消息的结论是错的，标题就该是"与事实不符"。）

**修完结果：谣言类恢复到 10/10，总分 15/19 = 78.9%。**

**教训**：给模型多一个档位 ≠ 更精细，它可能变成"逃避判断的出口"。
**每加一档判定，都必须用评测集回归一次。**

## 当前弱项：「尚无定论」类只答对 1/4

## 稳定性实测记录（2026-10-03）

首轮评测跑完后，我发现 **t05 两次运行的判定不同**，于是专门测了一轮。

**测试方法**：拿 t05 的原文，连续跑 3 次，看总判定。

| 轮次 | 总判定 | 拆出的断言 |
|---|---|---|
| 第一轮 3 次 | supported / mixed / supported | 2 条（措辞每次略不同） |
| 把 temperature 改成 0 之后再跑 3 次 | insufficient / mixed / supported | 2 条 |
| 加检索缓存后再跑 3 次 | supported / supported / refuted | 第 3 次的搜索关键词措辞不同 → 缓存未命中 → 搜到新证据 |
| **加结果缓存后** | **supported / supported / supported** | 一致，第 2、3 次耗时 0.0 秒 |

**结论**：
1. 方差的主因**不是模型温度**，而是「拆断言的措辞变化 → 搜索关键词变化 → 检索到不同证据」。
2. 只缓存搜索结果不够（关键词措辞一变就绕过缓存）。
3. 缓存**整条核查结果**（以输入文字的归一化哈希为键）才真正解决重复查询的一致性问题。

**这个发现意味着**：`RESULT.md` 里的准确率是**单次运行**的结果。
由于上述方差，同一份代码重复跑，个别样本的判定可能相差 1~2 条。
要更可靠的数字，需要跑多次取平均 —— **目前还没做**。

## 补测：证据固定后，判定本身稳不稳？（2026-10-03 第二轮）

上一轮把方差归因到"拆断言 + 检索"，但没有单独验证**判定这一步**稳不稳。
如果判定本身也摇摆，那缓存也救不了。于是做了隔离测试：

**方法**：先正常跑一次 t05 拿到 2 条断言 + 对应证据，**把这份证据固定住**，
然后只反复调「判定」这一步 3 次（`check.judge(cfg, claims, votes=1)`）。

**结果**：

| 第几次 | 总判定 | 逐条判定 |
|---|---|---|
| 1 | mixed | supported / **mixed** |
| 2 | mixed | supported / **mixed** |
| 3 | mixed | supported / **mixed** |

**3/3 完全一致。**

**同时验证了新加的规则**：t05 第 2 条断言「不用再经过单位了」以前会在
`refuted` 和 `supported` 之间跳；加了"**措辞绝对化 + 存在成文例外 → mixed**"这条规则后，
稳定判为 `mixed`，而且 reason 里同时写了中央口径和地方例外。

**据此定的设计**：
- `JUDGE_VOTES` 默认 **1**（判定稳定，没必要默认为每次付 3 倍钱）
- 要紧的核查可以设 3，平票时取最保守的一档 `insufficient`

**诚实说明**：这个稳定性结论只基于 **1 个样本 × 3 次**，样本量很小。
它配合"证据已固定"的机制推理才站得住，不能当成普遍保证。
严格的稳定性评测应该拿全部 19 条样本各跑 3 次 —— 那要花 3 倍的钱，暂未做。
